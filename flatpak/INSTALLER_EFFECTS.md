# BioSlicer Flatpak installer system effects

This document describes the behavior of `flatpak/install.sh` as of 2026-10-01.

It is the single installer for first install, updates and launching, and it has two
sources. By default it downloads `BioSlicer-<arch>.flatpak` (and its `.sha256`) from the
latest GitHub Release of `nicholas-karr/BioSlicer` (`BIOSLICER_VERSION=<tag>` picks another
release). When run with `BIOSLICER_URL=<url>`, or as a copy generated by `deploy.sh --url`, it
instead installs from an OSTree repo at `<url>/repo-<arch>`, where updates download only the
changed files. Users run it directly from the repository.

The installer is intentionally pragmatic: it may configure or repair a Linux or
WSL environment so the BioSlicer Flatpak can start. It is not a portable,
side-effect-free installer.

## Always performed

In this order:

- Detects the host as `x86_64` or `aarch64`. An unknown architecture falls back
  to `x86_64`.
- If the active `curl` comes from `/snap`, replaces it with the distribution's package
  (see "Package-manager changes"). This is the one system change made before the source
  is known to exist, because the check below needs a working `curl`.
- Verifies the source exists: the release's `.sha256` asset (release mode) or
  `<url>/repo-<arch>/summary` (repo mode). It exits with an error if not, before any of
  the changes listed below.
- Creates a private runtime directory under `/tmp/<uid>-runtime-dir` when
  `XDG_RUNTIME_DIR` is unset on non-WSL hosts.
- Adds or replaces a tagged `BIOSLICER-RUNTIME-*` block in `~/.bashrc`. The block
  creates that private runtime directory in future shells when needed.
- Adds the Flathub remote to the current user's Flatpak configuration if it does
  not already exist (the GNOME runtime comes from it).
- Stops running processes whose command line matches
  `flatpak run.*com.bioslicer.BioSlicer`.
- If an older system-wide `com.bioslicer.BioSlicer` installation exists, uninstalls it
  using `sudo flatpak uninstall --system`.

Release mode (default):

- Skips the download when the release's checksum matches
  `~/.local/share/bioslicer/installed.sha256` (written after each successful install)
  and the app is still installed from a bundle.
- Otherwise downloads the bundle to a temporary file (deleted on exit), compares it with
  the release's `.sha256` asset, and aborts on a mismatch. The checksum comes from the same
  GitHub Release, so it detects corruption, **not** tampering.
- Uninstalls an existing per-user `com.bioslicer.BioSlicer`, deletes per-user Flatpak
  remotes named `bioslicer.*-origin` (flatpak creates one per bundle install), and
  installs the bundle with `flatpak install --user --reinstall`.

Repo mode (`BIOSLICER_URL` or a `deploy.sh`-generated copy):

- Deletes `~/.local/share/bioslicer/installed.sha256`, since the bundle it describes is
  being replaced.

- Adds (or updates the URL of) a per-user Flatpak remote named `bioslicer`
  (`bioslicer<suffix>` for a suffixed channel) pointing at the repo, with GPG
  verification disabled because the repo is built locally and unsigned.
- If BioSlicer is already installed from that remote, runs `flatpak update`; only
  changed files are downloaded and "Nothing to do" is reported when current. A
  newer GNOME runtime from Flathub may also be fetched if one is available.
- Otherwise (first install, or an older bundle/other-remote install) uninstalls
  any per-user `com.bioslicer.BioSlicer`, cleans the `bioslicer.*-origin` remotes, and
  installs BioSlicer from the `bioslicer` remote.

Storage cleanup (both modes, after the install or update):

- Deletes every per-user Flatpak remote whose name starts with `bioslicer` other than
  the one BioSlicer is now installed from (bundle `-origin` remotes, and the remote of a
  previous source or channel).
- Unless BioSlicer was started again during the install, clears the app's cache. When a
  different build was installed it empties `~/.var/app/com.bioslicer.BioSlicer/cache`
  (Mesa shader cache, fontconfig cache, temp files; all regenerated on demand). Otherwise
  it empties only `cache/tmp` (the app's `/tmp`), removing temporary G-code left by the
  instances the installer stopped. Settings, profiles and presets under `config/` and
  `data/` are never touched.
- When the new build uses a different runtime than the previous one (e.g. GNOME 49 to
  50), uninstalls the previous per-user runtime unless it is pinned (installed explicitly)
  or another app still uses it.
- On Flatpak 1.10+ (which pins explicitly installed runtimes), runs
  `flatpak uninstall --user --unused`, removing per-user runtimes and extensions (GL
  drivers, codecs, locales) that no installed app uses. This applies to leftovers from
  any app, not just BioSlicer; pinned runtimes such as SDKs are kept.

- Creates or replaces `~/.local/bin/bioslicer` and marks it executable. The
  wrapper ultimately executes `flatpak run com.bioslicer.BioSlicer`.
- Launches BioSlicer immediately when a usable graphical/session environment is
  detected. Otherwise it leaves the application installed for later launch.

## Package-manager changes

When `flatpak` is absent, the installer uses the available package manager:

- APT: runs `apt-get update` and installs `flatpak` and `malcontent`.
- DNF: installs `flatpak` and `malcontent`.
- Pacman: installs `flatpak`.
- Zypper: installs `flatpak`.

On APT systems with Flatpak older than 1.14, it attempts to:

- install `software-properties-common`;
- add `ppa:flatpak/stable`;
- update APT package metadata; and
- upgrade/install `flatpak`.

On APT or DNF systems it also attempts to install `malcontent` when absent.

If the active `curl` executable comes from `/snap`, the installer removes the
Snap `curl` package and installs the distribution's `curl` package using APT,
DNF, Pacman, or Zypper.

## D-Bus changes

- If `/run/dbus/system_bus_socket` is absent and `dbus-daemon` is available, the
  installer creates `/run/dbus` with `sudo` and starts a root system bus using
  `dbus-daemon --system --fork --nopidfile`.
- If no session bus address is present and `dbus-launch` exists, it starts a
  session bus and exports its environment in the installer process.

The installer does not create a persistent system service for either bus.

## Additional WSL changes

On WSL, the installer:

- sets `XDG_RUNTIME_DIR` to `/run/user/<uid>`;
- creates that directory with `sudo`, changes it to the current user and group,
  and sets mode `0700`;
- may rewrite a relative `WAYLAND_DISPLAY` as an absolute WSLg socket path;
- creates or replaces `/usr/local/sbin/bioslicer-mkrundir`, owned according to
  the invoking system's `sudo tee` defaults and executable with mode `0755`;
- creates or replaces `/etc/sudoers.d/bioslicer-dbus` with mode `0440`;
- grants the current user `NOPASSWD` permission to run
  `/usr/local/sbin/bioslicer-mkrundir`; and
- when `dbus-daemon` is installed, grants the current user `NOPASSWD` permission
  to run its resolved path with exactly
  `--system --fork --nopidfile`.

The generated `bioslicer` wrapper uses those permissions on later launches to
recreate `/run/user/<uid>` and start the system D-Bus when necessary. These
`NOPASSWD` rules are deliberate installer behavior.

## Not performed

- The installer does not verify a signature or trusted publisher key. In release mode the
  checksum is fetched from the same release as the bundle; in repo mode the remote is
  added with `--no-gpg-verify` and OSTree only checks that each file matches its content
  hash. Authenticity rests on the TLS connection to GitHub or to the self-hosted server.
- It does not remove the `~/.bashrc` block, launcher, WSL helper, sudoers file,
  package-manager repositories, installed packages, or Flathub remote when the
  BioSlicer Flatpak is later uninstalled.
